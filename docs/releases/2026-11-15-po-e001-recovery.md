# PO E001 recovery deployment — 2026-11-15

PR #3 (merge `323f4e7`) was deployed to Docker server `10.60.10.59`, project `/root/budget-pulse-watch`. Only the `pronto_sync` worker was rebuilt and replaced; backend and frontend kept running. Roadmap: Phase 16. Working checklist: group A in `docs/backlog-dashboard-pronto-2026-11.md`.

## Problem

In the 2026-11-14 cycle, the first with PR #2, approval history was read for only 4 of 61 POs. PO 41562 is Cancelled in Pronto and has no PO. PO E001 answered its Find with "Record not found with key specified" and stayed in Find mode, and every later Find failed.

## Delivered behavior

- After a failed Find, the worker closes Pronto's message box with its own OK and leaves Find mode with Cancel.
- Before each PO, the worker brings PO E001 back to its order list.
- A transient Find failure is retried once.
- The sync report records why a PO was not read (`reason`, `message`).

## Deployment

The server's copies of `pronto_access.py` and `prf_pronto_sync.py` matched the pre-PR version (`68849fd`), so only the 4 changed files were copied (2 scripts, 2 test files), with `tar --no-overwrite-dir`. `docker compose -f docker-compose.production.yml build pronto_sync`, then `up -d --no-deps --no-build pronto_sync`.

Release tag: `pomon-pronto-sync:po-recovery-20261115`.
